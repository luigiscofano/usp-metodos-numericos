# Contribuir

Abra uma branch por mudança concreta: `fix/pivo`, `feat/metodo`, `docs/interpretacao` ou `test/convergencia`.

1. Registre um caso reproduzível, com seed e parâmetros.
2. Defina a métrica e o critério de aprovação antes de ajustar tolerâncias.
3. Preserve a distinção entre acervo e edição de estudo.
4. Execute testes e notebooks afetados.
5. Descreva no PR problema, resultado, evidência e limites.

Não regenere uma saída esperada apenas para esconder um erro. Não apresente resíduo como erro de solução, gráfico como prova de caos, dado sintético como medição real ou material fornecido como autoria exclusiva do aluno.

Não use datas retroativas, revisores fictícios ou PRs vazios para aumentar contagens. A política de redistribuição dos materiais recuperados não é ampliada pela publicação. Não foi atribuída uma licença permissiva global ao acervo.
